## 1. How does Orca know what each agent is doing (working / waiting / done / needs input)?

### Takeaway
Orca uses a layered scheme. The primary channel is per-agent managed hooks/plugins/extensions installed into each agent's own config; they POST JSON to a token-guarded loopback HTTP server inside the Orca app. Fallbacks are an in-band terminal protocol (OSC 7501 "Program Status", plus OSC 9999), terminal title/glyph parsing, a JSON rules engine over the rendered screen/title (used for `terminal wait --for tui-idle`), and process-presence probes. Hooks win by precedence. Official user docs undersell this ("OSC title sequence and agent hooks"); the code is much richer.

### Cited Findings

**State model**
- Canonical states are `working | blocked | waiting | done` (`AGENT_STATUS_STATES`). A row carries prompt, tool name/input preview, last assistant message, model, provider session id (for exact resume), subagent/child rows, `interrupted` flag, turn outcome, state history, and `restoredUnconfirmed` flag — [R/src/shared/agent-status-types.ts](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/src/shared/agent-status-types.ts)
- Mapping used by OSC 7501 projection: approvals/questions (turn-scoped blocked kinds) become `waiting`; other blocked kinds (e.g. sign-in) become `blocked`; OSC `done` -> done/success, `error` -> done/failure, `idle` -> rest (does not imply cancel) — [R/src/shared/program-status/agent-status-projector.ts](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/src/shared/program-status/agent-status-projector.ts)
- User-facing glyphs: spinner = working; amber question mark = waiting on you (permission/needs input); emerald check/dot = done; red dot = blocked/interrupted/failed; gray dot = idle; none = plain shell. Docs: "State is detected from the terminal's OSC title sequence and agent hooks" — [docs: model/agents-sessions.mdx](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/docs/site/content/docs/model/agents-sessions.mdx)
- Staleness: non-done rows with no evidence for 30 min decay (`AGENT_STATUS_STALE_AFTER_MS = 30 min`; the dashboard "Idle" column is "no completion reported for about 30 minutes"); persisted/hydrated rows are kept up to 7 days but are "unconfirmed" until live evidence arrives — [R/src/shared/agent-status-freshness.ts](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/src/shared/agent-status-freshness.ts)

**Channel 1: managed hooks (primary)**
- The agent-hooks README states there are two channels, both writing into the hook server's status store: (1) managed integrations (per-agent hooks, plugins, extensions that POST to the loopback hook server; carry state, prompt, tool name/input, assistant reply, provider session id, model, subagents) and (2) OSC 7501. "Precedence: hooks win, and OSC 7501 fills in wherever they don't speak" (hooks off, not installed e.g. fresh SSH host, programs with no integration, or hooks silent for 2 minutes on a state the program has since left) — [R/src/main/agent-hooks/README.md](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/src/main/agent-hooks/README.md)
- Installer registry lists 23 managed installers: claude, openclaude, codex, gemini, qoder, qoder-cn, qwen-code, codebuddy, antigravity, amp, cursor, droid, command-code, grok, copilot, hermes, devin, kimi, muse, zcode, dsh, jcode, kiro. Pi/OMP/OpenCode use extensions/plugins (README table "Orca integration" column: hooks / extension / plugin) — [R/src/main/agent-hooks/managed-agent-hook-registry.ts](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/src/main/agent-hooks/managed-agent-hook-registry.ts)
- Claude Code: Orca writes `type: "command"` hook entries (per issue #26718 into `~/.claude/settings.json`, script at `~/.orca/agent-hooks/claude-hook.sh`) for these events: SessionStart, UserPromptSubmit, Stop, StopFailure, SubagentStart, SubagentStop, TeammateIdle, PreToolUse(*), PostToolUse(*), PostToolUseFailure(*), PermissionRequest(*), PostCompact, Elicitation, ElicitationResult, and SessionEnd (only from Claude 2.1.261). Install set is version-gated by probing `claude --version`. It also installs a Claude statusLine entry (used for rate-limit data) — [R/src/main/claude/claude-managed-hook-events.ts](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/src/main/claude/claude-managed-hook-events.ts); [issue #26718](https://github.com/stablyai/orca/issues/26718)
- The hook script prints `{}` to stdout first (permission hooks fail closed on empty output), restores `ORCA_PANE_KEY` that `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB` strips, reads the endpoint file, POSTs the stdin JSON via curl, and spools the event to disk if Orca is unreachable. Windows variant uses a .cmd + curl. Process identity (`ps -o lstart`) is captured for liveness checks — [R/src/main/claude/hook-script.ts](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/src/main/claude/hook-script.ts)
- Transport: Node `http` server listening on `127.0.0.1` only, POST only, requires header `x-orca-agent-hook-token` (random UUID per app start, else 403), path routes by agent (`/hook/claude` etc.), plus special paths (Claude statusline, Claude agent view, OpenCode startup-prompt claim). Slowloris timeout. Body is run through "owner presence" checks, normalization, a disposition filter (suppress/restart/accept), then applied to the status store — [R/src/main/agent-hooks/server/server-lifecycle.ts](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/src/main/agent-hooks/server/server-lifecycle.ts); [R/src/shared/agent-hook-startup.ts](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/src/shared/agent-hook-startup.ts)
- Each PTY gets env `ORCA_AGENT_HOOK_PORT`, `ORCA_AGENT_HOOK_TOKEN`, `ORCA_AGENT_HOOK_ENV`, `ORCA_AGENT_HOOK_VERSION`, `ORCA_AGENT_HOOK_TRANSPORT`, `ORCA_AGENT_HOOK_ENDPOINT`, plus `ORCA_PANE_KEY` (pane identity, `${tabId}:${leafId}`). The endpoint file (`{userData}/agent-hooks/endpoint.env` on POSIX, `endpoint.cmd` on Windows) is re-sourced on every hook invocation so agents that outlive an Orca restart keep reporting — [R/src/main/agent-hooks/server/server-runtime-env.ts](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/src/main/agent-hooks/server/server-runtime-env.ts); [docs: agents/hooks-memory.mdx](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/docs/site/content/docs/agents/hooks-memory.mdx)
- Hooks can be toggled: Settings -> Agents -> Agent status hooks, or `orca agent hooks status|on|off --json`; turning off removes managed hooks, turning on restores without restart — hooks-memory.mdx (above) and [CLI reference](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/docs/site/content/docs/cli/reference.mdx)
- Remote/other hosts: SSH hosts get remote installers (`remote-managed-hook-installers.ts`), Windows/WSL get a hook relay (`wsl-hook-relay-*.ts`); other-host rows are tagged with a `connectionId` and mirrored — directory listing of [R/src/main/agent-hooks/](https://github.com/stablyai/orca/tree/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/src/main/agent-hooks)
- Anti-corruption logic is heavy: launch tokens, observation ordering/revisions, retired-pane fences, replay guards (Cursor/Grok import Claude hooks, Devin skip-duplicate logic), authority commitments persisted to `last-status.json` (throttled to one write per 5 s) — [R/src/main/agent-hooks/server/server-types.ts](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/src/main/agent-hooks/server/server-types.ts), [server-constants.ts](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/src/main/agent-hooks/server/server-constants.ts)

**Channel 2: OSC 7501 "Program Status Protocol" (agent self-reports in the terminal stream)**
- Orca reads OSC 7501 from PTY output and answers the protocol's `OSC 7501 ; ?` probe (spec at superlogical.com/rex/docs/build/program-status). Carries state, blocked `kind` (permission/question/auth), one free-text `msg`, child records. It cannot carry prompt, tool input, assistant reply, model, or session id, so agents cannot drop hooks for it today. Support matrix (last updated 2026-10-17): sends OSC 7501 — Claude Code (2.1.302, since 2.1.295; probe required), Grok 1.0.60, pi 1.3.0, oh-my-pi 18.10.3, Codex 0.163.0 (state only). Not sending — OpenCode, Kilocode, Cursor, Amp, Droid, Hermes, Muse, Devin, Kiro, Qoder, CodeBuddy, Jcode, Qwen/Freebuff/DeepSeek; others not checked — [R/src/main/agent-hooks/README.md](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/src/main/agent-hooks/README.md)
- Side effect: once Orca answers the probe, Claude Code stops putting its `⠂`/`✳` status glyph in the window title, so Orca's title trackers switch to reading OSC 7501 activity instead — same README (footnote 1).
- OSC 7501 records are projected onto agent-status payloads and ride "the OSC 9999 terminal-status ingress"; `\x1b]9999;` is a separate Orca in-band status prefix (agent-status-osc.ts) — [projector](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/src/shared/program-status/agent-status-projector.ts), [R/src/shared/agent-status-osc.ts](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/src/shared/agent-status-osc.ts)

**Channel 3: terminal title / glyph parsing**
- `agent-title-core.ts` classifies window titles per agent: braille/quarter-circle spinner glyphs = working, keyword regexes (`ready|idle|done` = idle; `working|thinking|running` = working; `action required|permission|waiting` = permission), Gemini-specific glyphs, Claude `✳` rest glyph, Cursor "Cursor Agent"/"Cursor ready"/"Cursor - action required", Pi/Droid/Hermes/Qoder/DSH name matchers. Return type `'working' | 'permission' | 'idle'` — [R/src/shared/agent-title-core.ts](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/src/shared/agent-title-core.ts)
- Docs say a pane with no indicator "isn't one Orca recognizes — start it through the agent combobox rather than typing the binary by hand" (agents-sessions.mdx).

**Channel 4: JSON rules engine over screen/title/text (powers `terminal wait --for tui-idle` and fallback readiness)**
- `src/main/runtime/agent-state-rules/` ships per-agent JSON rule files (claude, codex, cursor, gemini, opencode, opencode2, pi, omp, hermes, cline, dsh, prime-agent, antigravity, unknown-pane). Rules match "screen" rows (consecutive trimmed lines near bottom), "title" status, or "text" tail anchors; answers are `idle` (strong/weak, requiresQuiet) or `hold` (blocked/refusal). Patterns are length-capped (200 chars) and regex-safety checked — [schema](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/src/main/runtime/agent-state-rules/agent-state-rules-schema.ts), [claude.json](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/src/main/runtime/agent-state-rules/claude.json)
- Rules are live-updated: every 4 hours the app downloads `agent-state-rules.json` from a GitHub release tag `agent-state-rules-engine-<ver>-<stable|next>` (setting `agentStateRulesLiveUpdates`; packaged builds only) — [R/src/main/runtime/agent-state-rules/agent-state-rules-live-update.ts](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/src/main/runtime/agent-state-rules/agent-state-rules-live-update.ts)

**Channel 5: input-side inference and process presence**
- Interrupt inference: Escape / Ctrl+C keystrokes while a row is `working` can synthesize `done` + `interrupted` when the agent emits no cancel hook (guarded by baseline prompt/receivedAt match, 30-min freshness, double-Escape rules for TUIs where one Esc is navigation, child-work checks). Claude's Esc is confirmed by native title evidence — [R/src/main/agent-hooks/server/server-status-inference.ts](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/src/main/agent-hooks/server/server-status-inference.ts)
- Process presence: hook payloads carry a captured agent process identity; the server probes whether that process is still alive (`probeAgentProcessPresence`, `isSameAgentProcess`) and records "proven agent exits" (`agent-exit-evidence.ts`, `restored-status-dead-terminal-sweep.ts`) to retire rows after crashes/restarts — [R/src/main/agent-hooks/server/server-agent-presence.ts](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/src/main/agent-hooks/server/server-agent-presence.ts)
- Subagents/teammates: Claude SubagentStart/Stop and TeammateIdle build a roster; the lead's `Stop` is rewritten to `working` while child work is outstanding (see bug below).

**Which agent gets what** (README "Orca integration" column + docs): hooks — Claude, Codex, Cursor, Amp, Droid, Hermes, Muse, Devin, Kiro, Qoder, CodeBuddy, Jcode, Qwen Code, DSH, Gemini, Antigravity, Copilot, Kimi, Command Code, ZCode, OpenClaude, Grok; extension — pi, oh-my-pi (`src/main/pi/agent-status-extension-source.ts`); plugin — OpenCode (and Amp has a provider-native plugin). Docs "Supported agents": Orca works with any CLI agent as a plain terminal; "deep integration" is Claude, Codex, Cursor CLI, ZCode; status noted for OpenCode, Pi, OMP, Prime Agent, Antigravity, Ante, Command Code, DeepSeek, Droid — [docs: agents/supported.mdx](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/docs/site/content/docs/agents/supported.mdx). Note: Aider, Goose, Cline, Crush etc. are "Auto-setup" launchers only; they presumably rely on title/rules fallback (inferred; there is a `cline.json` rules file).

**Known limitations / bugs (open GitHub issues, as of 2026-10-26)**
- Hooks are installed once at app/runtime start; an agent CLI installed afterwards gets no hooks until restart, so approval prompts show as "working" (falls back to title) — [issue #28076](https://github.com/stablyai/orca/issues/28076)
- Hook endpoint resets connections on request bodies >= ~1 MB (e.g. large Claude PostToolUse `tool_response`), silently dropping events and leaving status stale — [issue #15791](https://github.com/stablyai/orca/issues/15791)
- A lost `SubagentStop` leaves a working row in the Claude roster with no expiry; every lead `Stop` is then rewritten to `working` for the rest of the session (also Qwen #26215, orphaned subagents block `agent_end` for pi #30230) — [issue #21327](https://github.com/stablyai/orca/issues/21327)
- Hooks are synchronous command hooks: ~9 process execs per event, p50 166 ms / p90 531 ms on a loaded macOS box (reporter's measurement); requests: mark async or use Claude `type: "http"` hooks — [#33451](https://github.com/stablyai/orca/issues/33451), [#26718](https://github.com/stablyai/orca/issues/26718)
- Claude hooks written to `~/.claude/settings.json` even with `CLAUDE_CONFIG_DIR` set, and managed-account dirs start with a settings.json holding only Orca hooks, shadowing the user's own layer — [#24873](https://github.com/stablyai/orca/issues/24873), [#23434](https://github.com/stablyai/orca/issues/23434); request to ship as a plugin [#15496](https://github.com/stablyai/orca/issues/15496)
- Other stuck/incorrect status reports: Cursor panes stay Working after stop hooks [#12686](https://github.com/stablyai/orca/issues/12686); Droid stays working after Ctrl+C [#9690](https://github.com/stablyai/orca/issues/9690); OMP 18 OSC 133 markers retire the pane mid-turn [#26933](https://github.com/stablyai/orca/issues/26933); DSH hook plugin installed-but-cannot-load reported as installed [#30173](https://github.com/stablyai/orca/issues/30173); `orca agent hooks status` doesn't cover SSH hosts [#27399](https://github.com/stablyai/orca/issues/27399); Hermes hooks only in default profile [#18259](https://github.com/stablyai/orca/issues/18259)
- `terminal wait --for tui-idle` is idle-of-agent-turn, not idle-of-human-typing — see CLI section issue #31195.

### Inferences
- Design philosophy: treat each agent's native hook surface as ground truth, then layer heuristics (title, screen rules, keystroke, process liveness) to repair the many cases where hooks go missing; most of the code volume is reconciliation/ordering logic, which suggests hook delivery is unreliable in practice (matches the open stuck-state bugs).
- Because the hook server is loopback + bearer token in env, any process in an Orca PTY can post forged status (token is in its env); this is a trust boundary, not a security boundary (not stated in docs; inferred from the code).
- The rule bundle download means status-detection behavior can change independent of app releases.

### Gaps
- Exact per-agent mapping of which native hook events map to `waiting` vs `blocked` vs `working` for each of the 23 agents was not enumerated (only the Claude event list and OSC mapping were read).
- No evidence found of process-tree/`ps` polling as a primary detector for agents lacking hooks; only presence verification for hook-bearing agents was found. Behavior for Aider/Goose/Crush etc. beyond title+rules is unverified.

## 2. How is it surfaced: dashboard, badges, notifications

### Takeaway
Status shows up as per-tab/worktree glyphs, an experimental kanban "Agent Dashboard" (Needs You / Working / Done / Idle), an "Agents" threaded feed, a header bell with unread count mirrored to the macOS Dock badge, OS notifications with optional sounds, and a mobile push path. Notification content includes a preview of the agent's last message or tool input.

### Cited Findings
- Agent Dashboard (Settings -> Experimental): kanban across worktrees; columns Needs You (waiting on permission/question), Working, Done, Idle (hidden by default; quiet ~30 min); cards show agent icon, session name, last user/agent message preview, host badge for SSH/remote servers; search + filters by project, workspace status, PR/MR status; in-window or pop-out; nested Codex/Claude subagents as expandable children — agents-sessions.mdx (above)
- Agents feed: sidebar entry (on by default) with a threaded feed of completions, blocking questions, unread state, worktree creation; running agents pinned on top; unread badge — [docs: activity.mdx](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/docs/site/content/docs/activity.mdx)
- Notifications doc: "When an agent transitions from working to idle, Orca fires a notification — system notification, sound, and a chip on the worktree." Header bell with unread across worktrees; macOS Dock badge mirrors unread count; right-click to mark unread; per-category toggles (system, sound, chip-only); custom sounds (MP3/WAV/OGG/M4A/AAC/FLAC) — [docs: notifications.mdx](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/docs/site/content/docs/notifications.mdx)
- Settings model: `enabled`, `agentTaskComplete`, `terminalBell`, `suppressWhenFocused`, sound id/path/volume, per-source mute list, `notifyHiddenWorkspaces`. Notification sources: `agent-task-complete`, `terminal-bell`, `test` (plus `plugin` on the push path) — [R/src/shared/notification-settings-types.ts](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/src/shared/notification-settings-types.ts)
- Wording is state-dependent: title is `<repo> / <worktree> - <Agent> <status>`; status text is "needs input" (waiting/blocked), "finished" (done/success), "failed" (failure/interruption), "stopped" (cancellation/superseded/unconfirmed), "working". Body = last assistant message (<=180 chars), else `Using <tool>: <input>`, else generic. Terminal bell: `Bell in <worktree>` — [R/src/main/ipc/notification-options.ts](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/src/main/ipc/notification-options.ts)
- Timing: 250 ms grace (max 1.5 s) so richer hook detail can win over a bare BEL; detail must be <=10 s old; input-needed states notify as soon as detail arrives, `done` waits for a quiet window (milestone done may resume); 5 s burst cooldown per key — [R/src/renderer/.../agent-task-complete-policy.ts](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/src/renderer/src/components/terminal-pane/agent-task-complete-policy.ts), [R/src/shared/notification-burst-cooldown.ts](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/src/shared/notification-burst-cooldown.ts)
- `session-boundary` dones (connect/resume/clear) are not turn completions; notifications/automations/badges ignore them (comment on `sessionBoundary`, STA-3386) — agent-status-types.ts.
- Notification suppression: `suppressWhenFocused`; per-worktree mute exists in runtime (`workspace-notification-mute.ts`) but a UI feature request is still open (#28289).
- Known issues: no way to notify phone only on "needs input" separate from "done" ([#33192](https://github.com/stablyai/orca/issues/33192)); route notifications by workspace/channel from CLI requested ([#33588](https://github.com/stablyai/orca/issues/33588)); exclude a paired machine from phone pushes ([#33777](https://github.com/stablyai/orca/issues/33777)); duplicate phone alerts when a runtime env is also paired with the phone, forwarded copy opens an empty workspace ([#28578](https://github.com/stablyai/orca/issues/28578)); macOS notification permission flag set without OS prompt ([#11675](https://github.com/stablyai/orca/issues/11675)); orchestration push-on-idle only delivers mail addressed to the terminal handle, not `run:<id>` mail ([#11787](https://github.com/stablyai/orca/issues/11787)).

### Inferences
- The notifications doc ("working to idle") understates the implementation: there is a distinct needs-input path with different timing than done.

### Gaps
- Dashboard is labelled Experimental in docs; no data on how many users enable it.

## 3. Mobile companion: pairing, relay, what is sent

### Takeaway
Pairing is QR/code-based and yields a per-device token and E2EE keys. The phone connects to the desktop over an E2EE WebSocket either directly (LAN/Tailscale, port 6768 by default) or via an Orca Relay (outbound WebSockets from both sides spliced by a cloud relay; requires Orca account sign-in). Push notifications go desktop -> push gateway (Cloud Run) -> APNs/FCM; the pushed title/body (up to 80/180 chars) include agent message previews in the gateway-visible payload.

### Cited Findings
- Mobile docs: iOS/Android beta companion; shows each worktree's agent and status (working / done / waiting on input) across all connected hosts; terminal scrollback, Chat UI (chat-style transcript for Claude/Codex etc.), reply to prompts (text, photo/file, dictation), Quick Commands, source control (stage/commit), browser view, account switching with usage, workspace creation. "The desktop is always the source of truth"; "Get push notifications when an agent finishes, mirroring desktop notifications" — [docs: mobile.mdx](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/docs/site/content/docs/mobile.mdx)
- Pairing: desktop shows a one-time pairing code/QR; mobile pastes/scans; exchange issues a device token; prefer Orca Relay (sign-in required only for Relay), LAN pairing needs an address; codes expire in minutes; "Closing the desktop app drops a direct/LAN session"; protocol version handshake via `status.get` (mobile.mdx; [mobile/README.md](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/mobile/README.md))
- Direct path: desktop hosts a WebSocket RPC server on port 6768 (`ws://<desktop-ip>:6768`); QR encodes endpoint, device token, TLS fingerprint — mobile/README.md
- E2EE: server X25519 secret key, shared-key derivation, encrypted frames, handshake timeout 10 s, device-key auth alternative to bearer token, v2 session — [R/src/main/runtime/rpc/e2ee-channel.ts](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/src/main/runtime/rpc/e2ee-channel.ts)
- Relay: "Phones and desktops never talk to each other directly: each opens an outbound WebSocket to a relay cell, the relay pairs the two sessions, and it splices frames between them. A director assigns hosts to cells." Public code in `cloud/` (relay, relay-contract, push, connector for an experimental Slack connector); production Terraform/runbooks are in private `stablyai/orca-cloud` — [R/cloud/README.md](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/cloud/README.md)
- Push path: phones hold no Orca credential for the gateway. The desktop host authenticates to the push gateway with its X25519 key (encrypted challenge -> 24 h session), registers each paired phone's native token (APNs/FCM), and asks the gateway to push. Gateway queues each event, enforces per-host quotas (300 events / 15 min, 64 devices/host, 5-minute TTL), retires dead tokens. "Provider push is the only ordinary mobile OS-banner path." FCM collapse semantics mean "every pending alert is not guaranteed." Logging is aggregate counters only: tokens, titles, bodies, full host fingerprints never reach a log line — cloud/README.md; [R/cloud/packages/push-contract/src/push-limits.ts](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/cloud/packages/push-contract/src/push-limits.ts)
- Push payload schema (strict): `notificationId`, seq/epoch, `source` (`agent-task-complete | terminal-bell | plugin`), `kind` (`alert|dismiss`), `agentState` (`needs-input | finished`), `title` (<=80), `body` (<=180), `worktreeId`, `paneKey`, `executionHost`; whole JSON <=3000 bytes — [R/cloud/packages/push-contract/src/send-messages.ts](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/cloud/packages/push-contract/src/send-messages.ts), [device-registration-messages.ts](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/cloud/packages/push-contract/src/device-registration-messages.ts)
- Windowless hosts (e.g. `orca serve`) push finish/input alerts to phones themselves using the desktop's rules (`TerminalAgentPhonePush`); if a desktop window owns the host it pushes instead; same 5 s burst gate; muted workspaces skipped — [R/src/main/runtime/terminal-agent-phone-push.ts](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/src/main/runtime/terminal-agent-phone-push.ts)
- Relay control protocol: host connects with a signed challenge, receives lease/generation/resume secret, relay announces `conn-open` with ticket for each phone connection; host attach deadline 10 s — [R/src/main/runtime/mobile-cloud-relay/relay-control-protocol.ts](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/src/main/runtime/mobile-cloud-relay/relay-control-protocol.ts)
- Open mobile/relay problems: Windows clock drift of 38 s breaks Relay and mobile only shows "host offline (4404)" ([#31799](https://github.com/stablyai/orca/issues/31799)); disconnects every few minutes over Tailscale ([#31580](https://github.com/stablyai/orca/issues/31580)); headless service cannot enroll mobile through Relay ([#27615](https://github.com/stablyai/orca/issues/27615), [#22278](https://github.com/stablyai/orca/issues/22278)); relay pairing fails with `relay_control_not_active` ([#11714](https://github.com/stablyai/orca/issues/11714)); proxy settings not honored for Cloud auth + Relay control ([#19976](https://github.com/stablyai/orca/issues/19976)); iOS background connection ([#27388](https://github.com/stablyai/orca/issues/27388)); PR proposing live-WebSocket local-notification fallback when native push is unavailable ([#32302](https://github.com/stablyai/orca/issues/32302)).

### Inferences
- Privacy: because the gateway must hand `title`/`body` to APNs/FCM, those fields (which can contain an assistant message preview or tool input such as a shell command) are visible to the push gateway and to Apple/Google in the clear, even though terminal/RPC traffic over the relay is E2EE. The README promises they are not logged. No setting to strip body content from pushes was found. This is inferred from the schema; not an explicit doc claim.
- Relay frames being E2EE is inferred from the shared E2EE channel + "splices frames" wording; the relay-contract E2EE layering was not read in full.

### Gaps
- Whether Relay data frames are end-to-end encrypted between phone and desktop (vs. only TLS to the relay) was not verified end-to-end.
- Relay/push gateway operation (hosting, retention) lives in the private `orca-cloud` repo and is not inspectable.

## 4. `orca` CLI: commands, JSON, IPC/API, MCP, agents driving agents

### Takeaway
The CLI is a thin client over a JSON-RPC runtime reached via a local Unix socket / Windows named pipe (token from `orca-runtime.json`), or WebSocket for paired/remote Orca servers. It exposes a very broad surface (worktrees, terminals, files, built-in browser automation, computer use, emulators, Linear/Jira/GitLab, automations, artifacts, hooks, skills) with `--json` envelopes, and a separate "orchestration" layer (runs, tasks, dispatches, mailboxes, decision gates) for agent-drives-agent. There is no Orca MCP server; instead Orca ships "skills" that teach agents to call the CLI.

### Cited Findings
- Transport: CLI reads `orca-runtime.json` (runtimeId, pid, `transports[]` of kind `unix` | `named-pipe` | `websocket`, authToken, startedAt) from the user-data dir and opens a `net` connection, framed as newline-delimited JSON with keepalive frames; client timeouts are explicit (`runtime_timeout`, `runtime_unavailable`) — [R/src/shared/runtime-bootstrap.ts](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/src/shared/runtime-bootstrap.ts), [R/src/cli/runtime/transport.ts](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/src/cli/runtime/transport.ts)
- Same RPC dispatcher serves Unix sockets, WebSockets and named pipes (`src/main/runtime/rpc/transport.ts`, `dispatcher.ts`, `methods/*`); mobile and remote clients use the WebSocket + E2EE variant. `orca serve --port 6768 --pairing-address <ip>` runs a headless runtime server; `orca environment add --pairing-code ...` pairs to a remote one; `--host local|ssh:<id>`, `--environment <name>` target hosts — [docs: cli/reference.mdx](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/docs/site/content/docs/cli/reference.mdx)
- No Orca MCP server found. The only `.mcp.json` in the repo is a dev fixture server. Docs: "Register MCP endpoints under Settings -> Integrations -> MCP; those tools appear inside agent CLIs that support MCP" (this is a config UI for the user's own MCP servers, plus `orca linear` implements Linear-MCP-compatible semantics such as `save-issue`) — [R/.mcp.json](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/.mcp.json), [docs: cli/skills.mdx](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/docs/site/content/docs/cli/skills.mdx)
- Agent integration is via skills: `npx skills add https://github.com/stablyai/orca --skill orca-cli` (also orchestration, computer-use, orca-linear, orca-emulator, orca-emulator-android, orca-per-workspace-env) or `orca skills install|update|get|list`. Public skills are thin "hybrid stubs"; `orca skills get <topic> [--full|--references|--reference name]` prints the version-matched guide from the binary so flags cannot drift — skills.mdx
- JSON output: `--json` everywhere; envelope `{id, ok, result, _meta}` (documented for `orchestration ask`); stable selectors `id:<repoId>::<path>`, `path:`, `branch:`, `issue:`, `name:`, `active|current` — reference.mdx, orchestration.mdx
- Command families (verified in reference.mdx): `open|status|serve`; `repo list|add|show|set-base-ref|search-refs`; `worktree list|ps|current|show|create|set|rm` (create takes `--agent --prompt --model --effort --setup --parent-worktree|--no-parent --pr --issue --reference ...`; `set` takes `--comment --workspace-status --unread|--read`); `agent launch`; `agent hooks status|on|off`; `terminal list|show|read|send|wait|create|split|rename|set-pane-title|switch|close`; `file open|diff|open-changed`; browser automation (`goto|snapshot|click|fill|wait|screenshot|tab *|console|network|pdf|exec|set device`); `computer *` (desktop apps); `emulator *` (iOS sim; Android via skill); `ports`; `reference add|list|remove|find`; `search` (conversation text); `linear *`, Jira, GitLab; `automations list|create|run`; `artifacts share|update|unshare|list|delete` (publishing off by default, human-only toggle); `account list|add`; `skills *`; `host list`.
- Reading agent status from the CLI: `orca worktree ps` is a "compact orchestration summary across worktrees"; `orca terminal show/list` expose handle/executionHost/liveness; `orca terminal wait --for exit|tui-idle --timeout-ms N` blocks until idle using the rules engine; `terminal read` returns accumulated stripped output with `--cursor` paging or `--screen` for the rendered frame — reference.mdx, [skill-guides/orca-cli.md](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/skill-guides/orca-cli.md), [src/cli/specs/core.ts](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/src/cli/specs/core.ts)
- Sending input: `terminal send --text --enter [--wait-submit N] [--retry-request id]`; receipts stage `input_accepted` -> `turn_started`; Orca refuses text+Enter prompts with `agent_prompt_blocked` while the agent shows a permission/trust menu; durable request ids allow safe retry; launches have `operationId` + `--retry-launch` replay — orca-cli.md
- Agent-drives-agent, lightweight: `orca worktree create --no-parent --agent codex --prompt "..."` for "full handoff"; `terminal send` for one-off prompts; worktree comments (`worktree set --comment`) as a progress line on the card; `worktree set --unread` raises the same unread dot as an agent finish — reference.mdx, orca-cli.md
- Agent-drives-agent, tracked (Experimental, enable in Settings -> Experimental): Run (namespace + coordinator inbox), Task (pending/ready/dispatched/completed/failed/blocked, with deps), Dispatch (one attempt on a terminal), Messages (`status|dispatch|worker_done|escalation|question|heartbeat`), decision gates. Commands: `run-create`, `task-create`, `worker-start --task --worktree current|new-child|new-top-level --agent --model --effort --setup [--on <host>]`, `check --wait --types ... --ack`, `send --to dispatch:<id>|run:<id>|@all|@idle|@claude|@worktree:<id>`, `ask` (blocking question with options and timeout), `gate-create/gate-resolve`, `worker-show|read|stop|release|retain`, `dispatch --inject`, `reset`. Workers must send `worker_done --outcome succeeded|failed` with task+dispatch ids; CLI prints heartbeat JSON to stderr every 15 s during waits; agent status rows carry orchestration context (taskId, dispatchId, attention) — [docs: cli/orchestration.mdx](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/docs/site/content/docs/cli/orchestration.mdx), agent-status-types.ts
- Linux binary is `orca-ide` (GNOME's screen reader owns `orca`) — reference.mdx.
- Known CLI/orchestration issues: `orca terminal send` text is typed into the target input line and can interleave with a human's in-progress typing; `tui-idle` does not detect human typing ([#31195](https://github.com/stablyai/orca/issues/31195)); codebuddy not injectable + Claude trust dialog breaks `wait tui-idle` readiness ([#25623](https://github.com/stablyai/orca/issues/25623)); initial prompt truncated/not submitted for Crush and OpenCode ([#22580](https://github.com/stablyai/orca/issues/22580)); skill install/update failures ([#30934](https://github.com/stablyai/orca/issues/30934), [#26758](https://github.com/stablyai/orca/issues/26758), [#11534](https://github.com/stablyai/orca/issues/11534)); Grok struggles with orchestration ([#18399](https://github.com/stablyai/orca/issues/18399)); orchestration push-on-idle gap ([#11787](https://github.com/stablyai/orca/issues/11787)); wake-recipient requests ([#18206](https://github.com/stablyai/orca/issues/18206), [#23417](https://github.com/stablyai/orca/issues/23417)).

### Inferences
- No documented stable public HTTP API for third parties: the local runtime socket and WebSocket RPC are internal (versioned protocol with compat gating for mobile), and the CLI is the supported scripting surface. A script could speak the socket protocol directly but that is unsupported (inferred).
- Orchestration is explicitly experimental and the legacy `orchestration run/coordinator-*` commands are retired no-ops, indicating the API is still churning.

### Gaps
- Exact fields returned by `worktree ps` / `terminal list` for agent status (e.g. whether `state` is exposed as `working|waiting|done`) were not confirmed; the spec text only says "compact orchestration summary".
- Whether a CLI command can subscribe/stream status changes (beyond `terminal wait` and `orchestration check --wait`) was not found.

## 5. PR/issue integrations and inline diff review

### Takeaway
GitHub integration is implemented by shelling out to the user's `gh` CLI (local or on the remote host), with rate-limit awareness; GitLab, Bitbucket, Azure DevOps, Gitea PRs and Linear/Jira issues are also supported. Diff review is an in-app diff viewer with line-anchored comments that are batched into a single prompt and typed into a chosen agent.

### Cited Findings
- GitHub: "Orca talks to GitHub through the GitHub CLI (`gh`) on your machine (or remote Orca host)"; classifies errors (rate limit, auth, 403, 404, network, gh missing); on rate limit keeps last known PR status and stops spawning `gh` calls for a short window; settings page shows "GitHub API Budget" — [docs: github-errors.mdx](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/docs/site/content/docs/github-errors.mdx)
- Features: link worktree <-> PR/MR with sidebar status; checks/reviews/comments inline in a PR tab; reply to any thread comment; reactions; **Fix broken checks** hands failing check names/links to an agent; auto-merge/merge queue; stacked PR creation and stack-aware merge; failed Actions show a red chip on the worktree; Projects view under "Tasks"; issue drawer with Activity timeline; create worktree from issue/PR opens the interactive composer and links the item. GitLab MRs/issues/pipelines, Bitbucket Cloud (API token), Azure DevOps and Gitea PRs also appear — [docs: review/github.mdx](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/docs/site/content/docs/review/github.mdx)
- Linear: personal API token in Settings -> Integrations; team picker; combined GitHub+Linear task drawer; worktree created from a Linear issue uses Linear's suggested branch name; inline images/media from issue description/comments/sub-issues are injected into the agent prompt; status sync is opt-in per team. Agents use `orca linear` (issue `--full`, `save-issue`, `list-issues`, relations, comments, attach) with Linear-MCP-compatible semantics. Jira is also supported (`orca jira`) — [docs: review/linear.mdx](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/docs/site/content/docs/review/linear.mdx), reference.mdx
- Worktree links: `orca worktree create --pr 123 | --issue 123 | --linear-issue | --gitlab-issue/--gitlab-mr | --reference <url>`; `orca reference add|list|remove|find` links multiple reviews/issues across providers to a workspace and returns `linkedItems` — reference.mdx
- Diff viewer: combined diff of staged/unstaged/untracked vs start-from ref (switchable), image diffs, HTML preview, three-way merge-conflict UI — [docs: review/diff-viewer.mdx](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/docs/site/content/docs/review/diff-viewer.mdx)
- Annotate AI Diff: hover line -> `+` (or `c`), markdown comment, comments pinned to lines and tracked across edits; **Send to agent** composes one prompt of all line-anchored comments and opens a "Send notes to" menu of the worktree's available agents (or start a new one); resolve threads; unresolved ones go in the next batch — [docs: review/annotate-ai-diff.mdx](https://github.com/stablyai/orca/blob/44d2fcb637f7736f66a9d3e7fee26516bf31daa8/docs/site/content/docs/review/annotate-ai-diff.mdx)
- RPC methods for these live in `src/main/runtime/rpc/methods/` (`github-*`, `gitlab.ts`, `hosted-review.ts`, `linear.ts`, `jira.ts`, `git-diff-methods.ts`), so mobile/remote clients use the same surface (directory listing).

### Inferences
- "Send to agent" most likely goes through the same terminal-input/agent-prompt submission path as `orca terminal send` (and so shares its interleaving risk, #31195). Not verified in code.
- Reliance on user's `gh` means GitHub rate limits are shared with agents' own `gh` usage (docs say this explicitly).

### Gaps
- Did not inspect how line comments are serialized into the prompt or the exact injection path.
- Did not verify Linear/Jira token storage (keychain vs file).
